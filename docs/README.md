## Описание

Сайт магазина настольных игр. Посетитель может посмотреть каталог, подобрать игру по числу игроков и длительности партии, открыть страницу любой игры, посмотреть корзину, доставку и контакты, отправить сообщение через форму обратной связи. Реализованы регистрация, вход в личный кабинет и оформление заказов с сохранением в базу данных.

## Технологии

- Фронтенд: HTML, CSS (Flexbox, Grid), JavaScript (fetch, async/await)
- Бэкенд: Python, FastAPI, SQLAlchemy
- База данных: SQLite
- Аутентификация: JWT, пароли хешируются bcrypt
- Развёртывание: Render (Web Service, сборка из GitHub)

## Переменные окружения

Ключи и параметры подключения не хранятся в коде. Скопируйте `.env.example` в `.env` и заполните значения (в репозиторий `.env` не попадает).

| Переменная | Назначение | Пример |
|---|---|---|
| `SECRET_KEY` | ключ подписи JWT-токенов | длинная случайная строка |
| `DATABASE_URL` | адрес базы данных | `sqlite:///./test.db` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | срок жизни токена | `60` |

Сгенерировать секретный ключ:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

## Запуск на своей машине

Проект состоит из бэкенда (FastAPI + SQLite) и фронтенда (HTML/CSS/JS). Нужно запустить оба.

### 1. Бэкенд

```bash
cd backend
pip install -r requirements.txt
cp .env.example .env        # затем впишите значения
python seed.py              # создаст test.db: 17 игр и пользователь test
uvicorn main:app --reload
```

Сервер: http://127.0.0.1:8000, документация: http://127.0.0.1:8000/docs

### 2. Фронтенд

В новом окне терминала, из корневой папки проекта (где лежит `index.html`):

```bash
python -m http.server 5500
```

Откройте http://localhost:5500/catalog.html

## Развёртывание на Render

1. Загрузите проект на GitHub. Файлы `.env` и `test.db` в репозиторий не добавляются (они в `.gitignore`).
2. На render.com создайте **New → Web Service** и подключите репозиторий.
3. Настройки сервиса:
   - Runtime: Python 3
   - Build Command: `pip install -r backend/requirements.txt`
   - Start Command: `cd backend && python seed.py && uvicorn main:app --host 0.0.0.0 --port $PORT`
4. В разделе **Environment** добавьте переменные из таблицы выше (`SECRET_KEY`, `DATABASE_URL` и др.).
5. Нажмите **Deploy**. HTTPS-сертификат Render выдаёт автоматически.
6. При каждом `git push` в основную ветку сервис пересобирается сам.

> На бесплатном тарифе файловая система Render временная: SQLite-база пересоздаётся при перезапуске, поэтому `seed.py` вызывается при старте. Для проверки это достаточно; зарегистрированные пользователи и заказы после перезапуска могут пропасть.

## Что сделано

### ПР 1: страницы и оформление

- Семь страниц: главная, каталог, страница игры, корзина, о нас, доставка, контакты, личный кабинет.
- Главная: подборка из 6 игр со ссылками на страницы игр.
- Семантическая разметка: `header`, `nav`, `main`, `article`, `footer`, один `h1` на странице.
- Собственный логотип (`images/logo.svg`).
- Макет на Flexbox и Grid, стили в одном файле.
- Адаптивность: при ширине 360 px горизонтальной прокрутки нет.
- Доступность: `alt` у всех изображений, видимый фокус при навигации Tab, подписи полей формы.

### ПР 2: поведение и внешние данные

- Две интерактивные формы: фильтр каталога (число игроков, длительность, сортировка) и форма обратной связи.
- Проверка данных до отправки: ошибки выводятся рядом с полем, фокус переходит на первое поле с ошибкой.
- Содержимое меняется без перезагрузки: фильтрация и сортировка сразу после выбора, счётчик и сообщение «ничего не найдено» обновляются автоматически, под ценой появляется пересчёт в доллары и евро.
- Внешний источник: курсы валют ЦБ РФ (https://www.cbr-xml-daily.ru/daily_json.js), запрос через `fetch` и `async/await`. Пока данные грузятся, показывается «Загружаем курсы ЦБ РФ…».
- Ошибки сети: понятное сообщение и кнопка «Повторить загрузку». Каталог и цены в рублях продолжают работать.

### ПР 3: сервер и база данных

**Схема базы данных (SQLite, 4 таблицы):**

| Таблица | Поля | Связи |
|---|---|---|
| `users` | id, username, password_hash | |
| `products` | id, name, price, min_players, max_players, play_time | |
| `orders` | id, user_id, product_id, quantity | `user_id` → `users.id`, `product_id` → `products.id` |
| `messages` | id, name, email, message | |

В `products` 17 игр с реальными названиями и характеристиками.

**API:**

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/products` | список всех игр |
| POST | `/api/register` | регистрация пользователя |
| POST | `/api/login` | вход, выдача JWT-токена |
| POST | `/api/orders` | создание заказа (только авторизованным) |
| GET | `/api/my-orders` | история заказов текущего пользователя |
| POST | `/api/messages` | сохранение сообщения из формы обратной связи |

Неверные запросы возвращают понятную ошибку с соответствующим HTTP-статусом.

**Связь с интерфейсом:** каталог, профиль и корзина получают данные с сервера, а не из жёстко прописанной разметки.

**Защищённый контент:** после входа пользователь видит профиль и историю заказов, недоступные неавторизованным. Права проверяются на сервере по JWT-токену.

**Безопасность:**
- пароли хранятся только в виде хеша (bcrypt);
- все SQL-запросы параметризованные (SQLAlchemy ORM), склейки строк нет.

### ПР 4: развёртывание

- Зависимости зафиксированы в `requirements.txt`.
- Секреты и параметры подключения вынесены в переменные окружения (`.env.example` в репозитории, `.env` нет).
- Запуск описан в README пошагово (локально и на Render): приложение собирается и запускается на чистой машине по инструкции. Docker не используется.
- Приложение размещено на Render и открывается по адресу в разделе «Ссылки».
- HTTPS включён, сертификат выдаётся автоматически.
- В README есть адрес приложения, инструкции запуска (локально и на Render), тестовая учётная запись.

## Как проверить

1. **Каталог.** Откройте `catalog.html`: игры загружаются из базы (в консоли браузера запрос `products` со статусом 200).
2. **Фильтр.** Выберите «5 и больше» игроков и «До 30 минут»: список сокращается, счётчик обновляется.
3. **Курсы валют.** Под ценами появляется пересчёт в доллары и евро. При отключении сети появляется сообщение об ошибке и кнопка повтора.
4. **Регистрация и вход.** В `profile.html` нажмите «Зарегистрироваться», создайте пользователя (пароль от 6 символов), затем войдите: появится блок профиля.
5. **Хеширование.** Откройте `backend/test.db` в DB Browser for SQLite, таблица `users`: в `password_hash` длинный хеш, а не пароль.
6. **Заказы.** Добавьте игры в корзину, нажмите «Оформить заказ»: в `profile.html` в «Истории заказов» появятся покупки.
7. **Обратная связь.** Отправьте сообщение через `contacts.html`: в таблице `messages` появится запись.
8. **Адаптивность.** В режиме устройства (F12, Ctrl+Shift+M) выставьте ширину 360 px: горизонтальной прокрутки нет.
9. **HTTPS.** Откройте адрес на Render: в адресной строке замок, предупреждений нет.
